# Agent Note: 开放自定义模型能力并拒绝空工具身份

Status: implemented

[English](2026-08-22-custom-model-capabilities-and-tool-identity.md) | 中文

## Problem

pi-ai 设置 schema 已能描述图片输入和按模型推理档位，但模型设置页只能编辑身份与容量。通过页面添加的模型因此仍会被视为纯文本，也不会显示推理选择器，除非运维者手工编辑 `settings.yaml`。另一方面，提供方给出不完整的工具调用身份时，`BlockAssembler` 会虚构调用 id 和空工具名。工具策略随后把空名称诊断成某个真实工具遭拒，提供方响应缺陷因而被隐藏在消费方专属错误之后。

## Decision

现有模型行的展开区使用「继承、仅文本、文本和图片」编辑 `input`，并用「继承、禁用、显式规范档位集合」编辑 `reasoningEfforts`。新档位采用自身的规范协议拼写；已有的非恒等协议拼写在无关编辑中保持不变。高级协议别名和 `compat` 继续留在 `settings.yaml`，不增加第二套 schema 编辑器。

`BlockAssembler` 要求每个保留的工具调用都携带非空白 id 和名称，缺失时抛出 code 为 `MALFORMED_RESPONSE` 的 `LlmError`，不再虚构任一值。达到最大 token 时仍在校验前丢弃工具调用，因为它们本就无法执行，也可能天然不完整。`MALFORMED_RESPONSE` 加入默认瞬态重试集合，因为失败尝试没有产生可执行的 assistant 消息。

## Alternatives considered

**假定所有自定义模型都接受图片和推理。** 拒绝，因为能力声明过宽会把清楚的本地拒绝变成用户消息已持久化后的提供方失败，而且各推理协议提供的档位并不一致。

**为整个模型 profile 增加通用 JSON 编辑器。** 拒绝，因为设置文档已经提供这个出口；重复其 schema、校验和帮助文本，比两个缺失的常用能力所需的界面更大。

**继续虚构工具 id，让工具策略拒绝空名称。** 拒绝，因为诊断指向错误的子系统，还可能针对模型从未标识的工具触发协调器行为。

## Verification

组件测试通过真实设置 mutation 载荷写入图片输入与推理档位。装配后的模型设置页快照记录手工声明提供方流程中的能力控件，并校验最终设置文档。装配器测试拒绝缺失 id 与空名称，同时保留最大 token 时丢弃工具调用以及回放对齐行为。

## Consequences

运维者无需离开界面即可如实声明 catalog 外的多模态或推理模型，会话选择器也会从同一份既有适配器元数据派生选项。自定义协议别名仍属于高级文本设置。畸形工具调用现在会在任何研究或工具守卫看到空工具名之前，以模型响应错误进行重试或失败。
